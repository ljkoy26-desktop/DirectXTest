# 로드카오스 스프라이트 구현 원리

DirectX7, DirectX11 샘플에서 노란 사각형 대신 로드카오스 캐릭터를 움직이는 방법을 정리한 문서입니다.

- 코드: `src/DirectX7/DirectX7.cpp`, `src/DirectX11/DirectX11/DirectX11.cpp`
- 이미지: 저장소 루트의 `로드카오스/` 폴더 (`creature_17611.png` ~ `creature_18042.png`, 432장)
- DirectX8은 Direct3D8 개발 파일(`d3d8.h`, `d3d8.lib`)을 구할 수 없어 적용하지 않았습니다.

---

## 1. 스프라이트 이미지 구성

### 1.1 파일 특징

- 프레임 1장 = PNG 파일 1개이며, 번호가 빠짐없이 이어집니다.
- 32bit RGBA PNG라서 배경은 알파값 0(투명)입니다.
- **프레임마다 이미지 크기가 다릅니다.** 캐릭터 둘레만 잘라낸 이미지라서 예를 들어 30×82, 78×113처럼 제각각입니다.
- 프레임별 위치 보정값(오프셋) 정보는 따로 없습니다.

### 1.2 동작 구간

사용하는 것은 앞쪽 192장(0~191번)입니다. 파일 번호 = `17611 + 프레임 번호`

| 동작 | 프레임 번호 | 파일 번호 | 방향당 프레임 수 |
|---|---|---|---|
| 대기 | 0 ~ 47 | 17611 ~ 17658 | 6 |
| 걷기 | 48 ~ 127 | 17659 ~ 17738 | 10 |
| 공격 | 128 ~ 191 | 17739 ~ 17802 | 8 |
| (미사용) 맞기·쓰러지기로 보임 | 192 ~ 431 | 17803 ~ 18042 | - |

### 1.3 방향 순서

모든 동작이 같은 방향 순서로 들어 있습니다.

| 방향 번호 | 방향 | 대기 | 걷기 | 공격 |
|---|---|---|---|---|
| 0 | 서 ← | 17611 ~ 17616 | 17659 ~ 17668 | 17739 ~ 17746 |
| 1 | 남서 ↙ | 17617 ~ 17622 | 17669 ~ 17678 | 17747 ~ 17754 |
| 2 | 남 ↓ | 17623 ~ 17628 | 17679 ~ 17688 | 17755 ~ 17762 |
| 3 | 남동 ↘ | 17629 ~ 17634 | 17689 ~ 17698 | 17763 ~ 17770 |
| 4 | 동 → | 17635 ~ 17640 | 17699 ~ 17708 | 17771 ~ 17778 |
| 5 | 북동 ↗ | 17641 ~ 17646 | 17709 ~ 17718 | 17779 ~ 17786 |
| 6 | 북 ↑ | 17647 ~ 17652 | 17719 ~ 17728 | 17787 ~ 17794 |
| 7 | 북서 ↖ | 17653 ~ 17658 | 17729 ~ 17738 | 17795 ~ 17802 |

그릴 프레임 번호는 다음 식으로 구합니다.

```
프레임 번호 = 동작 시작 번호 + 방향 번호 × 방향당 프레임 수 + 현재 애니메이션 프레임
```

예) 남동(3)으로 걷기 4번째 프레임(3) → `48 + 3 × 10 + 3 = 81` → `creature_17692.png`

## 2. 이미지 불러오기

### 2.1 폴더 찾기 — `FindSpriteDirectory()`

실행 파일 경로에서 상위 폴더로 한 단계씩(최대 8단계) 올라가며 `로드카오스\creature_17611.png`가 있는지 확인합니다.
그래서 Visual Studio에서 디버깅하든 exe를 직접 실행하든 저장소 안에서는 폴더를 찾을 수 있습니다.

### 2.2 PNG 읽기 — WIC (Windows Imaging Component)

Windows에 기본으로 들어 있는 WIC를 써서 별도 라이브러리 없이 PNG를 읽습니다.

1. `CoInitializeEx()` — WIC는 COM이라 프로그램 시작 시 초기화 (종료 시 `CoUninitialize()`)
2. `CoCreateInstance(CLSID_WICImagingFactory)` — 팩토리 생성
3. `CreateDecoderFromFilename()` → `GetFrame(0)` — PNG 열기
4. `CreateFormatConverter()` → `Initialize(GUID_WICPixelFormat32bppBGRA)` — 어떤 PNG든 32bit BGRA로 통일
5. `CopyPixels()` — 픽셀 배열로 복사

32bppBGRA는 메모리에 B, G, R, A 순으로 놓이며, `DWORD`로 읽으면 `0xAARRGGBB`가 됩니다.

## 3. 화면에 그리기

### 3.1 기준점: 발 위치

프레임마다 이미지 크기가 달라서 왼쪽 위를 기준으로 그리면 캐릭터가 위아래로 출렁입니다.
그래서 캐릭터 위치(`g_fPlayerX`, `g_fPlayerY`)를 **발 위치(이미지 아래쪽 가운데)** 로 두고 그립니다.

```
그릴 영역 왼쪽 = 발 X - 이미지 폭 / 2
그릴 영역 위쪽 = 발 Y - 이미지 높이
```

오프셋 정보가 없어서 걸을 때 좌우로 1~2픽셀 흔들려 보일 수 있습니다.

### 3.2 DirectX7 (DirectDraw) — 컬러키 방식

DirectDraw의 `Blt`는 알파 블렌딩을 지원하지 않아서 **컬러키**로 투명하게 처리합니다.

1. 프레임마다 이미지 크기의 오프스크린 서피스(`DDSCAPS_OFFSCREENPLAIN`)를 만듭니다.
2. 컬러키를 마젠타(255, 0, 255)로 정하고 `SetColorKey(DDCKEY_SRCBLT)`로 등록합니다.
3. `UploadSpritePixels()`에서 서피스를 `Lock`하고 픽셀을 씁니다.
   - 알파 < 128 → 컬러키 색으로 씀 (투명)
   - 알파 ≥ 128 → 원래 색으로 씀 (불투명)
   - 원래 색이 우연히 컬러키와 같으면 G값을 살짝 바꿔 구멍이 나지 않게 합니다.
   - `PackColor()`가 서피스 픽셀 포맷(16/24/32bit)의 RGB 마스크에 맞춰 색을 변환합니다.
4. `Blt(..., DDBLT_KEYSRC)`로 그리면 컬러키 색 픽셀은 건너뜁니다.
5. 백버퍼에 클리퍼가 없으므로 `DrawSprite()`에서 화면 밖으로 나간 부분을 직접 잘라냅니다.

**서피스 손실 대응**: 창 전환 등으로 서피스가 사라지면(`DDERR_SURFACELOST`) `RestoreAllSurfaces()`로 복구한 뒤 그림을 다시 올립니다.
이를 위해 PNG에서 읽은 픽셀을 `SpriteFrame::vecPixels`에 계속 보관합니다.

**한계**: 반투명 픽셀을 투명/불투명 둘 중 하나로 처리하므로 테두리가 딱 끊겨 보입니다.

### 3.3 DirectX11 (Direct3D 11) — 텍스처 + 셰이더 + 알파 블렌딩

1. 프레임마다 `DXGI_FORMAT_B8G8R8A8_UNORM` 텍스처(`D3D11_USAGE_IMMUTABLE`)와 셰이더 리소스 뷰(SRV)를 만듭니다.
   WIC의 BGRA와 포맷이 같아서 변환 없이 바로 올립니다.
2. `InitSpritePipeline()`에서 그리기 준비를 합니다.
   - 셰이더: 소스 문자열(`g_szSpriteShader`)을 실행할 때 `D3DCompile()`로 컴파일 (vs_4_0 / ps_4_0)
     - 정점 셰이더: 위치·UV를 그대로 넘김
     - 픽셀 셰이더: 텍스처 색을 그대로 출력
   - 정점 버퍼: 정점 4개짜리 동적 버퍼 (`D3D11_USAGE_DYNAMIC`)
   - 샘플러: `POINT` 필터 — 도트 그림이 뿌옇게 번지지 않도록
   - 블렌드: `SRC_ALPHA` / `INV_SRC_ALPHA` — PNG 알파값 그대로 반투명 합성
   - 래스터라이저: `CULL_NONE`
3. `DrawSprite()`에서 픽셀 좌표를 화면 좌표(-1 ~ 1, 위쪽이 +)로 바꿔 정점 버퍼에 쓰고(`Map(WRITE_DISCARD)`), 삼각형 스트립으로 사각형 하나를 그립니다.

```
x = 픽셀X / 640 × 2 - 1
y = -(픽셀Y / 480 × 2) + 1
```

DirectX7과 달리 테두리가 부드럽게 나오고, 화면 밖 부분은 GPU가 알아서 잘라냅니다.

## 4. 애니메이션과 입력 처리 — `UpdateInput()`

### 4.1 상태

| 변수 | 의미 |
|---|---|
| `g_nPlayerDir` | 바라보는 방향 (0~7) |
| `g_bPlayerWalk` | 걷는 중 |
| `g_bPlayerAttack` | 공격 중 |
| `g_fAnimTime` | 현재 동작이 시작된 뒤 지난 시간(초) |

- 대기·걷기: `(int)(g_fAnimTime × 12) % 방향당 프레임 수` → 초당 12프레임으로 반복
- 공격: `(int)(g_fAnimTime × 16)` → 초당 16프레임, 8프레임을 한 번만 재생 (약 0.5초)
- 동작이나 방향이 바뀌면 `g_fAnimTime`을 0으로 돌려 처음 프레임부터 재생

### 4.2 방향키 → 방향 번호

가로(-1, 0, +1) × 세로(-1, 0, +1) 입력을 표로 바꿉니다.

```cpp
static const int s_anDirTable[3][3] =
{
    //  x=-1  x=0  x=+1
    {   7,    6,   5 },  // y=-1 (위)
    {   0,   -1,   4 },  // y= 0       (-1 = 방향키 없음)
    {   1,    2,   3 },  // y=+1 (아래)
};
```

### 4.3 대각선 키를 뗄 때 방향 유지

↓ + → 를 누르고 있다가 손을 떼면 두 키가 정확히 동시에 떨어지지 않습니다.
한두 프레임 동안 한쪽 키만 눌린 상태가 되어 캐릭터가 정방향으로 돌아서 버립니다.

그래서 대각선 입력이 끝난 뒤 **0.1초(`DIAGONAL_RELEASE_SEC`) 안에** 그 대각선을 이루던 키 중 하나만 남아 있으면, 키를 떼는 중으로 보고 대각선 방향을 유지합니다.

### 4.4 공격 (A 키)

1. 방향키 입력과 대각선 처리를 **먼저** 계산합니다.
2. 공격 중이면 시간만 진행하고, 8프레임이 끝나면 공격 상태를 해제합니다. 공격 중에는 이동·방향 전환을 하지 않습니다.
3. A 키가 눌려 있으면 공격을 시작합니다. 이때 방향키가 함께 눌려 있으면 그 방향으로 먼저 돌아섭니다.
   - A를 누르고 있으면 공격이 끝날 때마다 다시 시작됩니다 (연속 공격).

### 4.5 이동

- 이동 거리 = `240픽셀/초 × 경과 시간` → 프레임 속도와 관계없이 같은 속도
- 대각선은 가로·세로에 각각 `1/√2(≈0.707)`를 곱해서 정방향과 같은 속도로 움직입니다.
- 발 위치가 화면 밖으로 나가지 않도록 가로 40픽셀, 위쪽 113픽셀(최대 프레임 높이) 여유를 둡니다.

## 5. 프레임 타이밍

| | DirectX7 | DirectX11 |
|---|---|---|
| 속도 제한 | 16ms 간격으로 직접 제한 (약 60FPS, `Blt`는 수직동기화를 기다리지 않음) | `Present(1)`이 수직동기화를 기다림 |
| 경과 시간 | `QueryPerformanceCounter` | `QueryPerformanceCounter` (최대 0.1초로 제한, 비활성 시간 무시) |

## 6. 주요 상수

| 상수 | 값 | 설명 |
|---|---|---|
| `SPRITE_FIRST_NUMBER` | 17611 | 첫 파일 번호 |
| `SPRITE_IDLE_FRAMES` / `WALK` / `ATTACK` | 6 / 10 / 8 | 방향당 프레임 수 |
| `SPRITE_ANIM_FPS` | 12 | 대기·걷기 애니메이션 속도 |
| `SPRITE_ATTACK_FPS` | 16 | 공격 애니메이션 속도 |
| `PLAYER_SPEED` | 240 | 초당 이동 픽셀 |
| `DIAGONAL_RELEASE_SEC` | 0.1 | 대각선 키를 뗄 때 허용 시간 |
| `SPRITE_HALF_WIDTH` / `SPRITE_HEIGHT` | 40 / 113 | 화면 경계 여유 |

다른 캐릭터로 바꿀 때는 폴더 이름(`SPRITE_DIR_NAME`), 첫 파일 번호, 동작별 프레임 수, 방향 순서(`s_anDirTable`)를 확인해서 맞춰야 합니다.
예를 들어 `축구훌리건`은 대기·걷기가 모두 방향당 6프레임이고 첫 번호가 1736입니다.
